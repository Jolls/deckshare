## How this zone is generated (read before editing)

`sqlc.yaml` (repo root) points at `queries: internal/db/queries`, `schema: migrations`,
`out: internal/db`, `sql_package: pgx/v5`, `emit_json_tags: true`, `emit_interface: true`.

**Any edit to a `.sql` file — including a comment-only edit — changes generated output.** sqlc
copies the comment lines preceding a `-- name:` annotation into the generated function's Go doc
comment. Verified: `internal/db/queries/media_refs.sql`'s "First-seen-wins" comment appears
verbatim above `func (q *Queries) CreateMediaRef` in `internal/db/media_refs.sql.go:25-27`.
Leading *file-level* comments attach to the file's first query (see
`internal/db/deletion.sql.go:128-133`, where `deletion.sql`'s three-line header is merged into
`LockDeckForDelete`'s doc comment).

So: after any `.sql` change, run `go generate ./...` and commit the regenerated `*.sql.go`.
Never hand-edit a `*.sql.go`.

## Findings and edits

### 1. `internal/db/queries/media_refs.sql` — undocumented `deck_access` exception

`ListMediaRefsForDeck` takes a bare `deck_id` and no `user_id`. It is authorised — its only
caller is `internal/review/batch.go:363` (`renderQueueRows`), reached from
`internal/http/review.go:40,102` only after `GetDeckForStudy` has passed `can_view AND can_study`
for that same deck id — but unlike `cards.sql`, `deletion.sql`, `export.sql`, and `import.sql`,
this file says nothing about why the §9 join is absent. Every other exception in the zone
carries that note.

**Edit.** In `internal/db/queries/media_refs.sql`, insert two comment lines directly above
line 4 (`-- name: ListMediaRefsForDeck :many`), so the file reads:

```
-- name: GetMediaRef :one
SELECT * FROM media_refs WHERE deck_id = $1 AND filename = $2;

-- No deck_access join (CLAUDE.md §9): the only caller is internal/review's renderQueueRows, for
-- a deck the review handler has already authorised with GetDeckForStudy (can_view AND can_study).
-- name: ListMediaRefsForDeck :many
SELECT * FROM media_refs WHERE deck_id = $1;
```

Comment-only, but it lands in `internal/db/media_refs.sql.go` as `ListMediaRefsForDeck`'s doc
comment — **run `go generate ./...` and commit the regenerated file.**

### 2. `internal/db/queries/notes.sql` — undocumented `deck_access` exception

`UpdateNoteContent` (lines 44-47) is the only write in `notes.sql` with neither a `deck_access`
join nor a comment. It is safe: both callers (`UpdateNoteWithCards` in `internal/db/notes.go:36`,
and nothing else) run it after `LockNoteForContentEdit`, which holds `FOR UPDATE OF n` on the note
row and has already checked `can_view AND can_edit_content`. Its neighbours `MoveNoteToDeck` and
`MoveNoteCardsFromDeck` both carry explanatory comments; this one does not.

**Edit.** In `internal/db/queries/notes.sql`, insert two comment lines directly above line 44
(`-- name: UpdateNoteContent :execrows`):

```
-- No deck_access join (CLAUDE.md §9): the caller (UpdateNoteWithCards) has already taken
-- LockNoteForContentEdit on this note, which authorises can_view + can_edit_content and holds the
-- row lock for the rest of the transaction.
-- name: UpdateNoteContent :execrows
```

Same regeneration requirement as Edit 1 — this becomes `UpdateNoteContent`'s doc comment in
`internal/db/notes.sql.go`.

### 3. `internal/db/cards.go` — nondeterministic destroy list

`SyncNoteCards` builds its delete list by ranging over the `existingByOrdinal` map, so the
ordinals handed to `DeleteCardsByOrdinals` arrive in Go's randomised map order. The `existing`
slice it was built from is already `ORDER BY ordinal` (`cards.sql:9`) and is right there. The
statement is `ordinal = ANY($2::int[])`, so element order is semantically irrelevant — this is
strictly a determinism/readability fix, not a correctness one, and the resulting set is identical
(`cards_note_id_ordinal_key` guarantees `existing` has no duplicate ordinals).

**Edit.** In `internal/db/cards.go`, replace lines 66-71:

```go
	var destroy []int32
	for ord := range existingByOrdinal {
		if _, ok := desiredByOrdinal[ord]; !ok {
			destroy = append(destroy, ord)
		}
	}
```

with:

```go
	var destroy []int32
	for _, c := range existing {
		if _, ok := desiredByOrdinal[c.Ordinal]; !ok {
			destroy = append(destroy, c.Ordinal)
		}
	}
```

`existing` was already in scope (line 37) and is still used to build `existingByOrdinal`;
`existingByOrdinal` is still used by the create loop at line 53. No variable becomes unused, no
import is orphaned. Pure Go change — no `go generate` needed.

### 4. `internal/db/errors.go` — duplicated `errors.As` inspection

`IsUniqueViolation` and `IsForeignKeyViolation` are byte-identical apart from the SQLSTATE
literal (`"23505"` vs `"23503"`). Both are exported and both have callers
(`internal/http/decks.go:88,239`, `internal/http/notetypes.go:78,206,229`, `cmd/seed/main.go:141`),
so neither name may change.

**Edit.** Replace the two function bodies in `internal/db/errors.go` (lines 12-28) with:

```go
func IsUniqueViolation(err error, constraint string) bool {
	return isPgErrOnConstraint(err, "23505", constraint)
}

// IsForeignKeyViolation reports whether err is a Postgres 23503 (foreign_key_violation) on the
// named constraint -- e.g. a note-type delete blocked by notes.note_type_id.
func IsForeignKeyViolation(err error, constraint string) bool {
	return isPgErrOnConstraint(err, "23503", constraint)
}

// isPgErrOnConstraint reports whether err carries a *pgconn.PgError with the given SQLSTATE code,
// raised by the named constraint.
func isPgErrOnConstraint(err error, code, constraint string) bool {
	var pgErr *pgconn.PgError
	if !errors.As(err, &pgErr) {
		return false
	}
	return pgErr.Code == code && pgErr.ConstraintName == constraint
}
```

Keep the existing doc comment above `IsUniqueViolation` unchanged (lines 9-11). Both `errors`
and `pgconn` are still used, by `isPgErrOnConstraint` — no import becomes orphaned. Pure Go
change — no `go generate` needed.

## Considered and rejected

- **Deleting the ten never-called queries.** `GetDeck`, `GetDeckAccess`, `GetDeckFsrsRetention`,
  `GetField`, `GetNote`, `GetReviewLogEntry`, `GetSession`, `GetTemplate`, `GetUserFsrsParams`,
  `ListNoteIDsOfNoteType` have zero references anywhere in the repo — production *or* test —
  outside their own generated `*.sql.go` and `querier.go`. That is ~60 lines of `.sql` and
  several hundred of generated Go. Not decided here: whether these are scaffolding leftovers or
  deliberate surface for Milestone 2 is a call the plan can't make. See Open questions.
  (Three more — `GetUser`, `GetMediaBlob`, `GetMediaRef` — are test-only and are *not* dead.)
- **Deduplicating `fieldOrderChanged` / `templateOrderChanged`** (`internal/db/notetypes.go:214-260`).
  Two 23-line functions, structurally identical, differing only in `[]Field`/`[]FieldEdit` vs
  `[]Template`/`[]TemplateEdit`. A Go generic with two id-extractor closures collapses them, but
  the repo currently contains **zero** generic functions (`grep -rn "^func [a-zA-Z]*\[" internal/ cmd/`
  returns nothing), so this would introduce a construct with no precedent, against CLAUDE.md
  working rule 3's "match existing style". The non-generic alternatives (extract to
  `[]pgtype.UUID` first, or hang `ID()` methods on the generated `Field`/`Template` structs) each
  need four new helpers to save one, i.e. net worse. See Open questions.
- **Deduplicating the repeated blocks in `internal/db/queries/reviews.sql`.** The `rev_cutoff`
  LATERAL subquery is byte-identical between `ListDueCardsForStudy` (lines 111-131) and
  `ListReviewCardsForStudy` (lines 225-245) — verified by `diff`. The new-card cutoff subselect
  is likewise identical modulo alias and indentation between `ListDueCardsForStudy` (149-158) and
  `ListNewCardsForStudy` (290-299). ~50 duplicated lines total. sqlc has no include/macro
  facility, so the only mechanisms are a database view or a SQL function — both new migrations,
  i.e. a schema change, which is out of scope for a no-behavior-change audit and would move
  hot-path query planning behind an object the planner treats differently. Not proposed.
- **Merging the four `GetDeckFor*` variants** (`GetDeckForUser`, `GetDeckForStudy`,
  `GetDeckForSettingsEdit`, `GetDeckForContentEdit`) into one query taking boolean
  require-flags. They differ only in which `deck_access` columns the join asserts. Rejected:
  CLAUDE.md §9's whole point is that authorisation is *explicit* at the query layer, and four
  named queries whose names state their permission are more legible than one query whose
  permission is a runtime argument. Same for `LockNoteForContentEdit` vs `GetNoteForContentEdit`
  (identical but for `FOR UPDATE OF n`) and `UpsertUserCardStateOnReview` vs
  `UpsertUserCardStateFromReplay` (identical but for the `last_review` guard) — both pairs are
  documented-deliberate.
- **Normalising `$1`-positional vs `sqlc.arg()` across `queries/*.sql`.** The two styles are
  mixed, sometimes within one file (`cards.sql` uses `$1..$4` in `CreateCard` and `sqlc.arg` in
  `DeleteCardsByOrdinals`). Rejected: converting a positional query changes the generated params
  struct's field names, hence every call site — that is not a no-behavior-change edit. The
  positional form's generated names are already column-derived and correct.
- **Iterating `desired` instead of `desiredByOrdinal` in `SyncNoteCards`'s create loop**
  (`internal/db/cards.go:52`), which would let the map be dropped. Rejected: the map silently
  dedupes duplicate ordinals, and nothing at the schema level forbids them — `fields`/`templates`
  ordinal indexes are non-unique by design (`migrations/00004`, `00005`). Ranging the slice would
  turn a currently-absorbed duplicate into a `cards_note_id_ordinal_key` violation. Behavior
  change; not in scope. (The *destroy* loop has no such hazard — that's Edit 3.)
- **Fixing the now-stale comment in `migrations/00008_notes.sql`** ("Nothing enforces that
  equality at the DB level -- by design... No trigger."), which migration `00015` superseded.
  Rejected outright: applied migrations are immutable (CLAUDE.md §9, §17). Fix forward only, and
  there is nothing to fix forward *to* for a comment. `docs/schema.md` was checked and is already
  correct (lines 56-61, 194 both describe the `00015` composite FK), so the stale text is
  confined to the frozen file and misleads nobody consulting the docs.
- **`review_log.card_id` as a real FK**, and **collapsing `(owner_id, guid)` / `(owner_id, name)`
  onto `anki_id`** — explicitly out of bounds per the issue and CLAUDE.md §2.2 / §2.5. Not raised.

## Resolved decisions

Answers to the Open questions above, decided with the user before implementation. These are the
spec; where they conflict with the sections above, these win.

### R1. Dead queries — delete the five unscoped getters, keep the other five

Resolves Open question 1 (option b), and also resolves #123's Open question 6.

The argument is not dead code, it is §9: these five are the only queries in the zone that read
deck-owned content with no `deck_access` join and no lock-based authorisation, sitting there for
someone to call by accident.

**Delete these five stanzas from the `.sql` sources:**

| Query | File |
|---|---|
| `GetDeck` | `internal/db/queries/decks.sql:1` |
| `GetDeckAccess` | `internal/db/queries/deck_access.sql:1` |
| `GetField` | `internal/db/queries/fields.sql:1` |
| `GetNote` | `internal/db/queries/notes.sql:1` |
| `GetTemplate` | `internal/db/queries/templates.sql:1` |

**Keep** `GetDeckFsrsRetention`, `GetReviewLogEntry`, `GetSession`, `GetUserFsrsParams`,
`ListNoteIDsOfNoteType` — they are user-scoped or otherwise not a §9 bypass, so CLAUDE.md rule 3
("don't remove pre-existing dead code unless asked") governs and they stay.

Then `go generate ./...` and commit the regenerated `decks.sql.go`, `deck_access.sql.go`,
`fields.sql.go`, `notes.sql.go`, `templates.sql.go`.

Verify before deleting each one: `grep -rn "<QueryName>" --include=*.go . | grep -v '\.sql\.go'`
must return nothing outside `querier.go`.

### R2. `emit_interface: false` — delete the generated Querier interface

Resolves Open question 2 (option a).

In `sqlc.yaml`, set `emit_interface: false`. `go generate ./...` then deletes
`internal/db/querier.go` (306 lines, no consumer anywhere — its only reference is the
`var _ Querier = (*Queries)(nil)` assertion inside itself). `git rm` it if generation leaves it
behind. Flipping the flag back restores it in one line if interface-based mocking is ever wanted.

**Sequencing note for #123:** #123's §2.2 says to commit a regenerated `querier.go` alongside
`sessions.sql.go`. After R2 that file no longer exists — #123 regenerates `sessions.sql.go` only.

### R3. `emit_json_tags: false` — regenerate without JSON tags, as its own commit

Resolves Open question 3 (option a).

No `db.*` struct is ever marshalled; every JSON wire type is hand-written in
`internal/review/types.go`, `internal/review/newlimit.go`, and `internal/http/review.go`. Tags on
db structs actively invite the wrong pattern — marshalling a `user_card_state` row, `stability`
and all, straight to a client — which invariant §2.7 exists to prevent.

**Apply this last, after every other edit in both groups**, and commit it alone. It is a pure
config-plus-regeneration change touching every struct in `models.go` and all remaining `*.sql.go`
files, so isolating it keeps the rest of the audit diff readable.

### R4. `fieldOrderChanged` / `templateOrderChanged` — leave both

Resolves Open question 4 (option b). No edit. The repo contains zero generic functions; making
these the first would be a construct with no precedent, against CLAUDE.md rule 3's "match existing
style", and the non-generic alternatives need four new helpers to save one.
